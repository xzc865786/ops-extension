# 支出体验优化与账号记录实施方案

2026-10-12 与用户讨论后确认。分两部分：支出记录／月度开支的体验优化（不改变金额、报销和数据保留规则），以及新增管理员“账号记录”页面。

## 一、支出记录与月度开支优化

金额计算、报销批次、并发与幂等规则沿用《支出记录与月度开支简化实施计划》，本次只调整交互和展示。

| 编号 | 调整 | 说明 |
| --- | --- | --- |
| 1 | 按付款人结清 | “待报销”视图顶部按付款人分组，显示笔数和人民币合计，点“结清”一次登记此人全部日期的待报销记录，不受分页限制；单批最多 100 笔，超出时提示分批。原勾选合并保留 |
| 2 | 原因对话框 | 作废、撤销报销改用页面内对话框填写原因，不再依赖 `window.prompt`（iframe 沙箱下可能被浏览器拦截） |
| 3 | 记一笔 | 字段顺序：买了什么 → 金额与币种（币种为切换按钮）→ 付款人 → 日期 → 分类；商家、备注收入“更多信息”，凭证保持可见；选择商家时带出该商家最近一次使用的分类；付款人下方显示最近使用的名字，点一下填入（初始仍为空）；新增“保存并再记一笔”，保留日期、付款人、分类，清空其余内容 |
| 4 | 人员汇总 | 页面列为付款人、垫付合计、已报销、待报销；差额不为 0 时提示；无需报销金额显示为“公司直付”。Excel 人员汇总表保留完整列以便对账 |
| 5 | 统计卡 | 月度开支顶部三张卡：本期总支出、待报销、比上期增减（上期为紧邻的等长日期区间）；分类汇总增加占比条 |
| 6 | 明细折叠 | 月度开支明细默认折叠，附“在支出记录中查看”跳转链接（带同一筛选）；导出不变 |
| 7 | 列表汇总行 | 支出记录列表显示当前筛选的笔数、人民币合计、其中待报销合计 |
| 8 | 操作列精简 | 列表只保留“复制一笔”“报销”，编辑、作废放到详情页；标题即详情链接 |
| 9 | 筛选与状态 | 筛选默认显示日期和关键词，付款人、分类、状态收入“更多筛选”；状态使用带颜色标签；付款人、关键词输入 300ms 防抖 |
| 10 | 显示格式 | 时间统一本地格式；撤销操作人显示名字；汇率说明简化为“按 1 美元 = x 元换算（汇率日期）”，来源与获取时间折叠显示 |

接口变化（均为新增字段或新增只读接口，原字段保留）：

- 列表响应新增 `summary`：`count`、`total_amount`、`pending_amount`。
- 新增 `GET /expense-records/pending-payers`：各付款人待报销笔数与合计（不限日期）。
- 新增 `GET /expense-records/pending?payer=`：该付款人全部待报销记录的编号与版本，用于结清。
- `meta` 新增 `recent_payers`（按最近使用排序）和 `merchant_categories`（商家 → 最近分类）。
- `monthly` 新增 `pending_amount`、`previous_total_amount`、`previous_range`；批次详情新增 `revoked_by_name`。

无数据库迁移。

## 二、账号记录

管理员页面 `/admin/accounts`，菜单名“账号记录”。用于登记团队注册的各类平台账号（Claude、ChatGPT、Google 等）及其使用状态。所有 Sub2API admin 均可查看和使用密码。不与支出记录关联，不提供 TOTP 验证码。

### 字段

| 字段 | 规则 |
| --- | --- |
| 客户端 | 必填，自由填写并提供 Claude、ChatGPT、Google、Gemini、Cursor、GitHub 等建议 |
| 登录账号 | 必填，通常为邮箱；同一客户端下（忽略大小写）未归档账号不可重复 |
| 密码 | 选填，加密保存 |
| 状态 | 启用、备用、封禁、停用；默认备用 |
| 套餐 | 选填，如 Plus、Pro、Max、Team |
| 到期日 | 选填；30 天内到期标黄，已过期标红 |
| 使用人 | 选填自由文本 |
| 绑定手机、辅助邮箱 | 选填 |
| 敏感备注 | 选填，加密保存，用于恢复码、密保问题等 |
| 备注 | 选填 |

删除改为“归档”：数据不物理删除，默认列表不显示，可在归档视图恢复。

### 页面

- 顶部按客户端分标签并显示数量；状态计数可点击筛选；关键词搜索账号、使用人、套餐、备注。
- 表格：客户端、账号（复制）、密码（`••••` + 查看／复制）、状态（可直接下拉修改）、套餐、到期日、使用人、更新时间。
- 新建、编辑在独立表单页；编辑时密码和敏感备注默认“不修改”，可选择修改或清空。
- 详情页显示全部字段和操作历史（含谁在何时查看或复制了密码）。

### 加密与审计

- 使用 AES-256-GCM（依赖 `cryptography`），密钥为环境变量 `ACCOUNT_VAULT_KEY`（32 字节随机值的 base64）。附加认证数据绑定账号编号与字段名，防止密文在记录间互换。保存密钥版本号，为将来轮换预留。
- 列表、详情接口只返回“是否已设置”，明文仅通过 `POST /admin/accounts/{id}/reveal` 获取；每次查看或复制都写入操作历史。前端 30 秒后自动隐藏明文。
- 修改密码只记录“密码已修改”，不记录新旧值；操作历史不保存任何明文或密文。
- 未配置密钥时，账号的其余信息正常可用；保存或查看密码返回“未配置加密密钥”，服务正常启动。
- 密钥必须与数据库备份分开保存；丢失密钥后已保存的密码无法恢复。
- 剪贴板在 iframe 中需要 `clipboard-write` 权限；不可用时退回为显示明文供手动复制。

### 数据库

新增迁移 `009`：`account_records`（含版本号用于并发冲突检查）与 `account_events`。不修改已有表。

2. 账号记录（迁移、模型、加密、接口与测试 → 前端页面与菜单）。
3. 更新 README、`.env.example`、部署文档。
4. 验证：后端完整 pytest；前端类型检查、构建、现有前端测试；隔离浏览器在 1440px 明暗主题和 390px 下实际操作。
