# 汇码智能新首页部署手册

本手册指导部署人员把新版首页（流光全息版）上线到 `https://api.tysy.top`，并替换 Sub2API 当前的首页内容。全程只新增一个静态页面，并修改 Sub2API 后台的一项设置。**不修改 Sub2API 源码、数据库或容器**，也不影响 Ops Extension（`/ext/*`）和使用手册（`/docs/`）。

预计耗时 30 分钟。按本手册操作前，请先通读一遍，并确认「6. 回滚」的备份已经做好。

## 0. 部署概览

### 0.1 要部署什么

| 项目 | 内容 |
| --- | --- |
| 页面文件 | 仓库 `main` 分支的 `homepage-designs/03-holo-pop.html`（单文件，已内嵌样式、脚本和官方 logo，不依赖任何外部 CDN 或字体） |
| 线上地址 | `https://api.tysy.top/landing/` |
| 服务器位置（建议） | `/srv/huima-landing/index.html` |
| Sub2API 设置 | 系统设置 → 通用设置 → 站点设置 → **首页内容**，改为 `https://api.tysy.top/landing/` |

### 0.2 工作原理

```text
访客打开 https://api.tysy.top/
  └─ Sub2API 首页：读取「首页内容」设置
       └─ 内容是 https:// 开头的地址 → 用全屏 iframe 加载它
            └─ https://api.tysy.top/landing/  ← Caddy 直接返回静态文件（本次新增）
```

**为什么不能把 HTML 直接粘贴进「首页内容」？** Sub2API 用 `v-html` 插入粘贴的 HTML，**页面里的 `<script>` 不会执行**。新首页的大部分区块依赖脚本才会显示，直接粘贴会出现大片空白，动画与互动也全部失效。所以必须用「填写网址」的方式。

**为什么要放在同一个域名下？**
- 页面会读取 Sub2API 的登录状态（浏览器本地存储），已登录用户会看到「进入控制台」。这只在同域名下有效。
- 「复制地址」按钮在同域 iframe 中才能正常使用剪贴板。
- 接入地址示例会自动显示为当前域名。

### 0.3 线上环境现状（2026-09-30 核对）

| 项目 | 现状 | 对部署的影响 |
| --- | --- | --- |
| Web 服务器 | **Caddy**（响应头 `server: Caddy`、`via: 1.1 Caddy`） | 按「2. 配置 Caddy」操作；Nginx 写法仅作备选 |
| `/docs/` 使用手册 | Caddy 直接提供的静态文件 | 新页面可参照它的配置方式 |
| Sub2API 页面响应头 | `X-Frame-Options: DENY`、`frame-ancestors 'none'` | 由 Sub2API 自身返回，**只作用于 Sub2API 的页面**；新页面必须由 Caddy 单独返回允许同域嵌入的响应头 |
| Sub2API 首页的 `frame-src` | 包含 `'self'` 和 `https://api.tysy.top` | 允许嵌入同域页面，无需改动 |
| `/landing/` 路径 | 目前未使用（落到 Sub2API 前端） | 可直接占用 |
| 当前「首页内容」 | 一段 HTML（`<div id="qiyuan-home">…`） | 上线前**必须先备份**，见 1.3 |
| 模型广场 | 未开启（`model_plaza_enabled: false`） | 新页面导航保留了「模型广场」入口，详见 7.3 |

## 1. 部署前准备

### 1.1 所需权限

- 服务器 SSH 权限，能修改 Caddy 配置并重载 Caddy。
- Sub2API **管理员**账号。

### 1.2 获取页面文件

在服务器上执行（`<仓库地址>` 替换为 Ops Extension 仓库的实际地址）：

```bash
# 首次获取
git clone <仓库地址> /opt/ops-extension
# 已有仓库时更新
cd /opt/ops-extension && git checkout main && git pull --ff-only

cd /opt/ops-extension
git log -1 --oneline -- homepage-designs/03-holo-pop.html   # 记录本次上线的提交号
```

如果服务器不方便使用 Git，也可以在本地下载该文件后用 `scp` 上传，效果相同。

### 1.3 备份当前首页内容（必做）

当前「首页内容」是一段 HTML。上线后这段内容会被覆盖，回滚时需要用到。在服务器或任意电脑上执行：

```bash
mkdir -p ~/huima-backup
curl -fsS https://api.tysy.top/api/v1/settings/public \
  | python3 -c 'import json,sys; print(json.load(sys.stdin)["data"]["home_content"])' \
  > ~/huima-backup/home_content-$(date +%F).html
wc -c ~/huima-backup/home_content-$(date +%F).html   # 应为 12 KB 左右，不能是 0
head -3 ~/huima-backup/home_content-$(date +%F).html  # 应以 <div id="qiyuan-home"> 开头
```

也可以在后台「首页内容」输入框里全选、复制，粘贴到文本文件保存。两种方式任选其一，但**必须确认备份文件有内容**。

### 1.4 检查页面配置

用文本编辑器打开 `homepage-designs/03-holo-pop.html`，搜索 `const SITE = {`，核对以下配置。**默认值已按线上站点填好，通常不需要修改**：

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `name` | `汇码智能` | 页面标题等处使用的站点名 |
| `fallbackOrigin` | `https://api.tysy.top` | 仅在本地双击预览时用于示例地址；线上自动取当前域名 |
| `links.login` | `/login` | 「登录」「免费开始」「领取我的钥匙」（未登录时） |
| `links.dashboard` / `adminDashboard` | `/dashboard` / `/admin/dashboard` | 已登录用户看到「进入控制台」时的跳转 |
| `links.models` | `/model-plaza` | 导航「模型广场」；填 `''` 即隐藏该入口 |
| `links.docs` | `/docs/` | 使用手册根地址；导航、首屏按钮、五步卡片、各工具教程都基于它 |
| `links.faq` / `contact` / `monitor` | `/docs/#troubleshooting` / `/docs/#contact` / `/monitor` | 页脚「常见问题」「联系客服」「渠道状态」 |
| `contactQQ` | `1045113768` | 页脚客服 QQ 群号；填 `''` 则不显示 |

任何一项填为 `''`（空字符串），对应的按钮或链接会自动隐藏。

## 2. 在服务器上放置页面

```bash
sudo mkdir -p /srv/huima-landing
sudo cp /opt/ops-extension/homepage-designs/03-holo-pop.html /srv/huima-landing/index.html
sudo chmod 755 /srv/huima-landing
sudo chmod 644 /srv/huima-landing/index.html
ls -l /srv/huima-landing/
```

- 文件名必须是 `index.html`，这样访问 `/landing/` 时会自动返回它。
- 目录和文件需要 Caddy 进程可读。以上权限对系统服务方式运行的 Caddy 足够。
- **Caddy 运行在 Docker 中时**，容器看不到宿主机的 `/srv/huima-landing`，需要在 Caddy 的 Compose 文件中增加只读挂载，并重建 Caddy 容器：

  ```yaml
  services:
    caddy:            # 以实际服务名为准
      volumes:
        - /srv/huima-landing:/srv/huima-landing:ro
  ```

  然后执行 `docker compose up -d caddy`。挂载后容器内路径与宿主机一致，下一节的 Caddy 配置可以原样使用。

## 3. 配置 Caddy

### 3.1 找到站点配置

```bash
# 系统服务方式
systemctl status caddy --no-pager | head -5
ls /etc/caddy/                   # 通常是 /etc/caddy/Caddyfile

# Docker 方式
docker ps --format '{{.Names}}\t{{.Image}}' | grep -i caddy
docker exec <caddy容器名> cat /etc/caddy/Caddyfile
```

在 Caddyfile 中找到 `api.tysy.top { … }` 站点块。其中应当已有 `/docs/` 的静态文件配置，以及把其余请求转发给 Sub2API 的 `reverse_proxy`。

**修改前先备份：**

```bash
sudo cp /etc/caddy/Caddyfile /etc/caddy/Caddyfile.bak-$(date +%F)
```

### 3.2 加入新首页的规则

在 `api.tysy.top { … }` 站点块内加入下面这段。建议放在 `/docs/` 规则旁边，**不要改动其他已有规则**：

```caddyfile
	# ---- 汇码智能新首页（由 Sub2API「首页内容」以 iframe 嵌入）----
	redir /landing /landing/ 308
	handle_path /landing/* {
		root * /srv/huima-landing
		encode zstd gzip
		header {
			# 只允许被本站页面嵌入；页面脚本和样式是内联的，不请求任何外部资源
			Content-Security-Policy "default-src 'none'; script-src 'unsafe-inline'; style-src 'unsafe-inline'; img-src 'self' data:; base-uri 'none'; form-action 'none'; object-src 'none'; frame-ancestors 'self'"
			-X-Frame-Options
			X-Content-Type-Options "nosniff"
			Referrer-Policy "strict-origin-when-cross-origin"
			Cache-Control "no-cache"
		}
		file_server
	}
```

逐行说明：

| 配置 | 作用 |
| --- | --- |
| `redir /landing /landing/ 308` | 访问不带斜杠的 `/landing` 时补上斜杠 |
| `handle_path /landing/*` | 拦截 `/landing/` 下的请求并去掉前缀，因此 `/landing/` 对应目录里的 `index.html`。`handle` 类规则在 Caddy 中先于 `reverse_proxy` 执行，这些请求不会再转给 Sub2API |
| `encode zstd gzip` | 压缩传输，页面约 68 KB，压缩后约 23 KB。只写在本规则内，**不要放到站点级别**：放到站点级别会作用于 API 的流式响应 |
| `frame-ancestors 'self'` | **关键**：允许被同域的 Sub2API 首页嵌入，禁止被其他网站嵌入 |
| `-X-Frame-Options` | 如果站点块有全局 `header` 设置了 `X-Frame-Options: DENY`，在这里去掉，否则 iframe 会空白 |
| `script-src 'unsafe-inline'` 等 | 页面是单文件，脚本和样式都内联。页面不读取网址参数，也不展示用户输入的内容，没有可注入的入口。同时 `default-src 'none'` 禁止加载任何外部脚本、样式、字体和网络请求 |
| `Cache-Control "no-cache"` | 浏览器每次都会校验更新，以后替换文件能立即生效 |

> 如果站点块里的 `/docs/` 用的是 `handle /docs/* { … }` 写法，而不是 `handle_path`，保持它不变即可，两种写法可以共存。

### 3.3 校验并重载

```bash
# 系统服务方式
sudo caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile
sudo systemctl reload caddy

# Docker 方式
docker exec <caddy容器名> caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile
docker exec <caddy容器名> caddy reload --config /etc/caddy/Caddyfile --adapter caddyfile
```

`validate` 报错时**不要重载**，先修正配置。重载是平滑的，不会中断现有访问。

### 3.4 备选：使用 Nginx 时

如果以后改用 Nginx，在 `api.tysy.top` 的 `server {}` 中加入以下配置，效果等同：

```nginx
location = /landing { return 308 /landing/; }

location ^~ /landing/ {
    alias /srv/huima-landing/;
    index index.html;
    # add_header 会覆盖外层同名设置；这里显式给出本页需要的全部响应头
    add_header Content-Security-Policy "default-src 'none'; script-src 'unsafe-inline'; style-src 'unsafe-inline'; img-src 'self' data:; base-uri 'none'; form-action 'none'; object-src 'none'; frame-ancestors 'self'" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header Referrer-Policy "strict-origin-when-cross-origin" always;
    add_header Cache-Control "no-cache" always;
}
```

同时确认这个 `location` 中没有继承 `X-Frame-Options DENY`。然后执行 `sudo nginx -t && sudo systemctl reload nginx`。

## 4. 验证页面（切换首页之前）

先直接访问新页面，确认没问题后再修改 Sub2API 设置。此时线上首页还没有变化，访客不受影响。

### 4.1 命令行检查

```bash
curl -sS -o /dev/null -w '%{http_code} %{content_type}\n' https://api.tysy.top/landing/
curl -sSI https://api.tysy.top/landing/ | grep -iE 'content-security-policy|x-frame-options|cache-control'
curl -sS https://api.tysy.top/landing/ | grep -o '<title>[^<]*</title>'
curl -sS -o /dev/null -w '%{http_code} -> %{redirect_url}\n' https://api.tysy.top/landing
```

| 检查 | 预期结果 |
| --- | --- |
| 第 1 条 | `200 text/html; charset=utf-8` |
| 第 2 条 | 出现 `frame-ancestors 'self'`、`cache-control: no-cache`；**不能出现** `x-frame-options: DENY` |
| 第 3 条 | `<title>汇码智能 · 一把钥匙，打开所有 AI</title>` |
| 第 4 条 | `308 -> https://api.tysy.top/landing/` |

如果第 2 条出现的是 `frame-ancestors 'none'` 或 `x-frame-options: DENY`，说明请求仍然转给了 Sub2API，或者被全局响应头覆盖了，按「8. 常见问题」排查。

### 4.2 浏览器检查

用浏览器直接打开 `https://api.tysy.top/landing/`，按 F12 打开开发者工具的 Console（控制台）：

- 页面完整显示：大标题逐字弹入，钥匙卡会随鼠标倾斜。
- Console 中**没有**红色的 `Content Security Policy` 报错。

## 5. 切换 Sub2API 首页

1. 用管理员账号登录 `https://api.tysy.top`。
2. 进入 **系统设置 → 通用设置 → 站点设置**，找到 **首页内容**。
3. 确认已按 1.3 完成备份，然后清空输入框，只填入下面一行（前后不要有空格或换行）：

   ```text
   https://api.tysy.top/landing/
   ```

4. 保存设置。
5. 用**无痕窗口**打开 `https://api.tysy.top/`（避免旧缓存），应显示新首页。

**说明：** 首页内容改为网址后，Sub2API 首页不再显示它自带的状态信息，属于正常现象。站点设置里的其他项（站点名称、Logo、文档链接等）不受影响。

## 7. 日常维护

### 7.1 更新页面

页面是静态文件，更新**不需要重载 Caddy**：

```bash
cd /opt/ops-extension && git pull --ff-only
sudo cp /srv/huima-landing/index.html /srv/huima-landing/index.html.bak-$(date +%F)
sudo cp homepage-designs/03-holo-pop.html /srv/huima-landing/index.html
```

因为设置了 `Cache-Control: no-cache`，访客刷新后即可看到新版。如果站点前面还有 CDN，需要在 CDN 上刷新 `/landing/` 的缓存。

### 7.2 常见修改位置

| 想修改的内容 | 在页面文件中搜索 |
| --- | --- |
| 站点名称、各按钮跳转地址、客服 QQ 群 | `const SITE = {` |
| 「连接软件」各工具的填写内容、提醒和教程链接 | `const TOOLS = {` |
| 已接入的模型（顶部标签、钥匙卡、滚动字幕） | `已接入`、`class="models"`、`class="marquee"` |
| 五步卡片文案 | `class="steps"` |

「上手五步」和「连接软件」的内容取自 `/docs/` 使用手册（2026-09 版）。**使用手册中的接口地址或步骤变化时，需同步修改页面中的 `TOOLS` 数据**，避免首页和手册说法不一致。

### 7.3 模型广场入口

导航中的「模型广场」按计划预留，站点目前**未开启**模型广场。开启之前，访客点击这个入口会回到首页，已登录用户会进入控制台。不会报错，但入口看起来没有反应。

已确认后续开启模型广场，步骤见 [模型广场开启指南](./模型广场开启指南.md)。开启后入口即可使用，页面无需修改。如果开启时间较晚，也可以暂时把页面中的 `links.models` 改为 `''` 隐藏入口，开启后再恢复为 `'/model-plaza'`。

### 7.4 品牌名称

已确认（2026-09-30）：**新首页使用「汇码智能」，使用手册和 Sub2API 后台保留「汇码」**。部署时不要修改后台的站点名称。

后台站点 Logo 可以换成官方图形标识 `homepage-designs/brand/huima_symbol_color.svg`（不含文字，与「汇码」不冲突），详见《使用手册优化建议》C5。这一项与首页上线互不依赖，可以单独安排。

## 8. 回滚

### 8.1 恢复原首页（1 分钟）

1. 进入 **系统设置 → 通用设置 → 站点设置 → 首页内容**。
2. 清空输入框，粘贴 1.3 备份文件的**全部内容**，保存。
3. 无痕窗口打开首页，确认已恢复为旧版。

只需这一步即可恢复，`/landing/` 页面和 Caddy 配置可以保留，不影响线上。

### 8.2 完全撤除（可选）

需要彻底移除新页面时，删除 3.2 中加入的配置段，校验并重载 Caddy（见 3.3），再删除 `/srv/huima-landing` 目录。

## 9. 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 首页一片空白 | iframe 被拒绝加载。执行 4.1 第 2 条：出现 `x-frame-options: DENY` 或 `frame-ancestors 'none'`，说明 `/landing/` 的请求没有命中新规则，或被全局 `header` 覆盖。确认 3.2 的配置位于 `api.tysy.top` 站点块内、Caddy 已重载；存在全局 `header` 时确认保留了 `-X-Frame-Options` |
| 直接打开 `/landing/` 显示 Sub2API 页面或 404 | 规则未生效，或文件路径不对。检查 `ls -l /srv/huima-landing/index.html`；Docker 部署时检查挂载，可执行 `docker exec <caddy容器名> ls /srv/huima-landing` |
| 页面只有标题和部分文字，大片空白、没有动画 | 脚本被安全策略拦截。F12 查看 Console 的 CSP 报错，确认响应头与 3.2 **完全一致**（包含 `script-src 'unsafe-inline'`）。如果「首页内容」里粘贴的是 HTML 而不是网址，也会出现这种情况 |
| 点「登录」后登录页出现在首页框里 | 页面文件被改动过，或不是最新版本。重新复制仓库中的文件；页面脚本会给所有站内链接加上跳出框架的设置 |
| 显示的还是旧首页 | 浏览器缓存了站点设置。用无痕窗口或强制刷新（Ctrl+F5）；确认后台设置已保存 |
| 地址显示的不是 `https://api.tysy.top` | 页面不是通过 `api.tysy.top` 打开的，例如直接双击了本地文件。线上访问时会自动显示当前域名 |
| 「复制」没有反应 | 剪贴板功能需要 HTTPS 和同域嵌入。确认首页内容填的是 `https://api.tysy.top/landing/`，而不是 http 地址或其他域名 |
| 已登录却仍显示「免费开始」 | 登录状态只在同域下可读。确认使用的是 `api.tysy.top` 域名；退出重新登录后再试 |
