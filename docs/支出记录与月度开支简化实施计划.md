# 支出记录与月度开支简化实施计划

将现有报账审批系统调整为管理员共用的支出台账。日常操作是填写支出、自动换算或手动调整人民币金额、登记报销、按月导出。本计划供实施 agent 直接执行，当前交付仅为计划，不包含业务代码修改。

2026-10-11 产品调整：支出记录与月度开支统一沿用旧版双日历日期区间选择器，快捷项放在展开日历侧边，支持本月、上月、本季度、上季度及跨月份自定义范围；默认本月，待报销默认不限日期。移除历史单据页面入口、人工核对迁入表单、页面及导出的历史未核对提示，旧数据留在数据库，不自动迁入，后续重新填报。此调整取代下文原有的单月份控件和历史展示／人工迁入要求，金额、报销及数据保留规则继续有效。

## 已确定的产品规则

| 事项 | 实施规则 |
| --- | --- |
| 使用人员 | 继续仅允许管理员访问；付款人可以是任意人，不要求是系统用户 |
| 付款人 | 自由填写，初始为空，不默认管理员，不自动使用登录人姓名；提供历史名称建议但不强制选择 |
| 操作人 | 系统自动记录谁创建、修改、登记或撤销报销，与付款人分开 |
| 币种 | 新记录支持人民币 CNY 和美元 USD |
| 美元换算 | 输入金额后获取录入当天最新可用参考汇率，自动计算人民币金额；用户可直接修改人民币结果 |
| 补记过去支出 | 支出日期决定归属月份，但默认换算仍用录入当天最新可用汇率；不实现此前讨论过的自动按历史支出日期取汇率 |
| 人民币平账 | 汇总、导出、默认应报销金额统一使用最终保存的人民币金额 |
| 汇率固定 | 保存原币、参考汇率及人民币结果；保存后不随外部汇率自动变化 |
| 年付支出 | 全额计入支出日期所在月份，不按服务期限分摊 |
| 报销状态 | 待报销、已报销、无需报销；是否需要报销由用户选择，不根据付款人名称推断 |
| 默认状态 | 新建默认需要报销；保存即为待报销并计入支出统计，无提交或审批步骤 |
| 一期报销 | 整笔或同一付款人的多笔一起结清，不做分次报销、审批或支付渠道集成 |
| 报销与费用 | 报销只是偿还垫款，不能再计一次支出；实际报销金额与记账金额可以不同，差额单独保留 |

一期不做成本中心、付款账户建档、发票税务管理、数量乘单价明细、预算、自动续费、自动分摊、其他新币种或自动转账。已有相关数据保留为历史资料。

## 页面和操作流程

### 支出记录

保留前端路径 `/admin/expenses`，菜单及标题改为“支出记录”，主按钮改为“记一笔”。保留已有 Sub2API bootstrap 链接，不因改名更换嵌入路径。

- 快捷筛选：全部、待报销、我录入的。付款人是自由文本，因此不要实现成通过登录用户 ID 推断“我垫付的”。
- 其他筛选：支出月份或全部月份、付款人、分类、报销状态、关键词。关键词搜索购买内容、商家、备注及付款人。
- 默认查看本月全部有效记录；点击“待报销”快捷入口时明确切到全部月份，避免漏掉往月垫款；界面可见当前日期范围。
- 列表列：支出日期、买了什么、分类、付款人、原币金额、折合人民币、报销状态、操作。
- 提供分页和总条数，不沿用现有只取前 50 条而没有翻页的行为。勾选限当前页，切页或更改筛选清空选中项。
- 单笔操作：详情、编辑、复制一笔、登记报销、作废；批量操作仅提供同一付款人的待报销记录合并报销。
- 作废记录默认隐藏，单独可查；已报销记录先撤销所属报销批次后才能作废或修改核心金额等信息。
- 历史单据入口放在此页次级操作中，不增加第三个主菜单。存在未核对历史记录时显示数量及对统计完整性的提示。

### 记一笔和编辑

复用 `ExpenseForm.vue` 对应的新建、编辑路由。无需为了简化业务而同时引入新的弹窗或抽屉框架。

| 字段 | 交互与校验 |
| --- | --- |
| 买了什么 | 必填简短标题，例如“新加坡服务器 10 月续费” |
| 支出日期 | 默认北京时间当天，可补记；决定报表归属月份 |
| 分类 | 必选，有合理默认；常用分类排前，保留其他；新选择中移除“员工垫付”，付款方式不能作为用途分类 |
| 付款人 | 必填自由文本，初始为空；去除首尾空格；建议已有名称，不进行模糊合并或按系统账号绑定 |
| 金额和币种 | 金额大于零，最多两位小数；币种默认 CNY，可切换 USD |
| 折合人民币 | 仅 USD 展示，自动计算且可直接编辑；最终值必须大于零、最多两位小数 |
| 是否需要报销 | 默认需要；关闭后保存为无需报销 |
| 商家或平台 | 选填自由文本，历史值建议，不要求主数据建档 |
| 付款凭证 | 选填，录入时选文件即可；复用已有存储、格式和大小限制 |
| 备注 | 选填，不强制重复填写购买内容 |

人民币只填写一个金额，人民币记账额等于原金额，不展示第二个可编辑金额。付款人去除首尾空格后精确相同才归为同一人，例如“张三”和“小张”不得自动合并。

美元输入流程：输入金额 → 显示自动换算结果 → 可修改人民币金额 → 保存。汇率来源、有效日期及获取时间可查看，统一展示方向“1 美元 = x 人民币”。

- 手动修改人民币金额后标记“已手动调整”，保留原参考汇率，不把反算出的比值伪称为外部汇率。
- 自动模式下修改美元原金额可以重新计算；手动模式下修改原金额须提示“保留手填人民币金额”或“重新换算”，选择前不能保存旧的、不经确认的结果。
- “按最新汇率重新换算”是明确的用户操作，可以覆盖手填结果；背景请求、重载、编辑页初始化不能覆盖手填值。
- 从 USD 切换 CNY 后人民币值应等于当前原金额，并清理不适用的汇率状态；切回 USD 重新执行换算流程。
- 异步汇率请求只允许最新请求更新界面；币种切换、金额变化或手动输入后，过期响应不能回写。
- 编辑已保存记录时先回显原值，不自动取新汇率重算；复制一笔时日期为今天、付款人清空、金额等内容可复制，但报销状态重置，USD 重新取最新汇率，附件和报销凭证不复制。
- 凭证上传失败时保留已创建记录并提示重试；重试只能补传附件，不能重复创建支出。保存按钮防连点，并为创建请求提供幂等保障。

### 详情和登记报销

复用 `/admin/expenses/:id`，展示购买内容、付款人、原币、参考汇率、最终人民币金额、报销状态、附件和操作历史。取消原审批、发票税务及同币种付款表单。

“登记报销”可以单笔或批量打开：显示付款人、所选支出、人民币应报销合计；输入实际报销人民币金额、报销日期，选填转账凭证和备注。默认实际金额等于应报销合计，日期为北京时间当天。按钮文案为“确认已报销”，不表示系统实际转账。

- 同一批可以包含 CNY 和 USD 支出，但付款人必须精确相同，且所有记录都必须有效、待报销。
- 实际金额与应报销合计不一致时，要求填写差额说明，并明确该操作仍表示整批结清；一期不支持把少付金额登记为部分报销。
- 默认逐笔实际金额等于各笔人民币记账额；调整批次总额时，按各笔记账额比例分配到分，展示分配预览后确认。
- 分配采用整数分和最大余数法，余数相同按记录 ID 排序；逐笔分配金额非负，合计严格等于批次实际金额。批次总额必须大于零。
- 每笔保存应报销额、实际分配额和差额，不能将批次总额重复记在每笔上。付款人总额、单据明细和报销凭证必须能互相核对。
- 报销成功后记录变为已报销，原人民币记账额保持不变。
- 撤销按整个批次进行，显示受影响记录、要求填写原因；原批次和凭证保留，记录回到待报销。撤销仅更正登记，不执行资金退回。
- 已报销记录核心字段不可直接修改；金额、币种、人民币额、付款人、支出日期、是否报销的更正须先撤销报销。所有更正记录前后值、操作人和时间。

### 月度开支

保留 `/admin/reports`，菜单和标题改为“月度开支”。默认本月，支持上月和月份选择；必要时复用现有日期区间能力，不再展示八种报表选项。

- 核心汇总：所选月份支出总额，单位人民币。
- 分类汇总：各用途的人民币金额及笔数。
- 人员汇总：所选月份各付款人的需报销记账额、当前待报销额、已结清记账额、实际已报销额和差额；无需报销金额单独标明，不计入人员欠款。
- 明细：日期、购买内容、分类、商家、付款人、原币金额、人民币金额、状态、报销日期和备注。详细汇率信息可在详情和导出中查看。
- 所有这些汇总均以支出日期筛选；已报销金额表示这些支出的累计有效报销分配额，不是所选月份发生的转账流水，标签和帮助文字明确说明。
- 全部月份的欠款由“支出记录 → 待报销”查看。报销日期不能改变支出归属月份。
- 年付、待报销、已报销、无需报销的有效支出都计入费用；作废和未确认的历史记录不计入。

一个“导出 Excel”按钮，导出完整筛选结果而非当前页，使用三张中文工作表：支出明细、分类汇总、人员汇总。页面与导出使用同一查询和计算逻辑。

明细保留：记录编号、支出日期、购买内容、分类中文名、商家、付款人、币种、原币金额、参考汇率及有效日期、参考汇率来源、自动或手动金额标记、人民币记账额、报销状态、实际报销额、差额、报销日期、报销批次号、备注。无需报销记录的实报金额留空，不伪装成已付款。

导出金额为数值单元格、显示两位小数，筛选条件和未确认历史记录数量放在说明区域。付款人、标题等用户文本必须作为文本写入，防止被 Excel 当作公式执行。普通导出不携带会过期的附件签名链接或存储内部地址。

## 汇率和金额实现约束

实施默认选择后端代理获取最新参考汇率，不让浏览器直接依赖外部汇率服务。可使用项目已有 `httpx`，无须新增大型 SDK。

第一版建议采用 Frankfurter v2 的 USD/CNY 最新参考汇率接口。其官方说明提供最新和历史汇率、公开接口无需 API key、数据按日更新；这属于自动查询最新参考汇率，不是逐秒市场报价。页面不能标注“实时成交价”。实施时验证接口响应、USD/CNY 可用性和部署环境网络，不把本文示例汇率写入产品。[Frankfurter 官方文档](https://frankfurter.dev/)

- 将汇率服务封装为可替换 provider，默认通过固定配置请求 `https://api.frankfurter.dev/v2/rate/usd/cny`。第一版不增加付费订阅要求。
- 响应包含汇率、数据有效日期、获取时间、来源。周末节假日如最新有效日期早于今天，明确显示该日期，不谎称今日发布。
- 使用短超时和有上限的缓存，例如 30 分钟；手动刷新尝试刷新缓存，失败显示失败，不把缓存值标成新获取。缓存不是已保存账目重估机制。
- 汇率获取失败可以重试或直接手填人民币金额并保存；此时参考汇率为空，来源标记为人工填写，禁止默认汇率 1 或伪造参考汇率。
- 自动模式采用服务端保存的汇率快照或可校验引用，服务端计算最终金额；手动模式尊重用户人民币结果，保留参考快照。保存到最终记录的快照不能只依赖临时缓存。
- 前后端金额通过十进制字符串传递。后端用 Decimal，金额数据库列用 Numeric；计算后按 ROUND_HALF_UP 四舍五入到分。汇率保留至少 8 位小数，不使用浮点数累加金额。
- 汇总求各笔已保存人民币金额之和，不先汇总美元再按现价换算。实际报销分配额也逐笔按分保存和汇总。
- 时间戳保存带时区时间；支出和报销日期是日期类型，默认日期及按日汇率请求口径使用 Asia/Shanghai，避免 `toISOString().slice(0, 10)` 在北京时间凌晨落到前一天。

## 数据结构和接口边界

建议采用新的轻量台账模型，与原审批单据保留关联；不将原 `ExpensePayment` 同币种付款流水直接改造成人民币报销记录。这样可以保留旧资料，也不必用虚假的审批状态驱动新流程。具体文件拆分可以由实施 agent 结合仓库惯例完成，但以下数据语义和约束不能省略。

| 实体 | 必须保存的语义 |
| --- | --- |
| 支出记录 | 标题、支出日期、分类、付款人文本、商家文本、原币及金额、最终人民币额、自动或手动模式、参考汇率快照、是否需报销、有效或作废状态、备注、操作人、版本号、可空且唯一的旧单据关联 |
| 报销批次 | 付款人快照、实际人民币总额、报销日期、备注或差额原因、有效或已撤销状态、登记人、撤销人及原因、幂等键 |
| 报销关联明细 | 支出 ID、批次 ID、当时应报销人民币快照、实际分配人民币额、差额；一笔支出最多关联一个有效报销批次 |
| 附件 | 明确属于支出凭证或报销批次凭证；保存现有存储元信息；旧附件仍按旧归属下载 |
| 操作事件 | 创建、编辑、作废、报销、撤销、历史确认的前后值及操作人；不硬删报销历史 |

报销状态可以由是否需要报销和有效批次关联推导。如果选择冗余状态字段，必须在同一事务内维护一致性。不要新增可被随意覆盖的“已付总额”作为唯一事实来源。

建议新业务 API 使用 `/ext/api/v1/admin/expense-records` 和 `/ext/api/v1/admin/reimbursements`，避免悄悄改变旧接口语义。前端入口 URL 保持不变。

| 能力 | 建议接口职责 |
| --- | --- |
| 台账 | 分页列表、创建、详情、更新、作废；复制可由新建表单预填后走创建接口 |
| 常用信息 | 分类、付款人和商家名称建议；付款人建议不查询管理员列表作为默认值 |
| 汇率 | 获取最新 USD/CNY 报价及快照引用，支持显式刷新 |
| 报销 | 新建批次、详情、撤销整个批次；统一处理单笔与多笔 |
| 月报 | 新人民币汇总、分类、人员、明细及中文 Excel 导出，共享筛选逻辑 |
| 历史 | 原单只读查看、待核对列表、确认迁入；每张原单最多迁入一次 |

所有新接口及附件下载保持管理员权限。附件下载必须识别新支出和报销批次来源，不复用相同数字 ID 去猜测属于哪个表。现有工单附件权限和下载行为不变。

创建及报销请求需幂等。报销事务按固定顺序锁定所选支出，重新验证状态、付款人、版本和金额，批次及明细全成功或全失败；重复点击、网络重试和两个管理员并发操作都不得产生重复报销。编辑、作废和撤销使用相同并发约束，旧版本请求返回明确冲突提示。

迁移采用新增表和索引，当前已检查的 Alembic 最新 revision 为 `007`；实施时重新检查实际 head，再追加迁移，不修改已经部署的历史 migration。新增模型沿用仓库 BigInt 类型适配及 SQLite 测试兼容方式。

## 历史数据处理和上线边界

现有单据有审批状态、付款流水和多币种，但缺少可靠的自由填写付款人及最终人民币金额。“申请人”不一定是付款人，“已付款”也不能直接证明已经向垫付人报销。

默认保留原报账单、明细、税务、付款记录、附件和事件，在新页面提供历史只读入口。不要用最新汇率批量改写旧金额，不把申请人批量填成付款人，不删除旧表。

迁入流程：查看原单 → 人工确认付款人、购买内容、支出日期、人民币金额和报销情况 → 保存为新台账记录，并记录原单关联与确认人。

- 旧 CNY 金额可以作为人民币预填值；旧 USD 原金额保留，但人民币值由管理员确认。历史迁入不自动以今天汇率认定旧账。
- 旧已付记录只有在确认属于报销、金额和日期有依据时才建立历史报销批次；无法确定的保留为待核对，不把它伪装成待报销或已报销。
- 旧部分付款、跨币种异常、零金额、已取消以及 CNY/USD 以外币种都保留原始信息，不能直接套用正常新记录校验后丢弃；需要补齐有效新账信息后才能迁入。
- 未迁入记录不进入新人民币总额，页面及导出明确显示“历史未核对记录未计入”及数量。新旧数据不得重复计算。
- 迁入有唯一约束与事务，重复确认不重复创建支出；既有凭证通过原单关联可访问，无须搬运或复制对象存储文件。
- 提供只读盘点或 dry-run 输出，列出状态、币种、付款异常、附件数量及待确认数量，用于上线核对。

切换后旧费用写接口应明确返回“请使用新版支出记录”，避免旧浏览器继续创建不进入新报表的数据；旧读取和附件下载继续可用。旧报表接口保留时必须明确其历史口径，不能返回旧数据却冒充新版人民币总额。旧主数据页面移出日常导航，作为历史资料保留；种子脚本不能成为新记账流程的前置条件。

准备数据库备份和回退步骤，但实施 agent 不得以本计划为授权修改生产财务数据或直接上线。先在隔离环境完成新增迁移、功能验证和历史盘点。应用回滚不得直接删除含有新记账或报销记录的表；新旧写入切换策略、旧接口恢复方式和已产生新数据的保留方式必须记录。

## 测试和验收

以下是实施验收要求，不是已经通过的测试结果。对金额、状态转换、并发和迁移写有实际业务价值的测试，避免只验证字段名称或组件内部实现。

| 场景 | 必须验证的结果 |
| --- | --- |
| 付款人 | 新建为空、必填、任意名字均可；操作人独立；名称建议不强制绑定账号 |
| CNY 支出 | 保存 100 元立即计入月报，待报销 100 元，无审批步骤 |
| USD 自动 | 模拟汇率 7.10，20 美元保存为 142.00 元；之后汇率改变，旧账仍为 142.00 元 |
| USD 手动 | 将上述结果改为 143.26 元；详情、月报、导出、默认报销都为 143.26 元，参考汇率仍保留 7.10 |
| 失败与异步 | 无网络可手填保存且参考汇率为空；慢响应不能覆盖手填、已切换币种或新输入；编辑不自动重估 |
| 日期 | 补记旧月按支出日期归属，自动报价按录入当天最新数据；北京时间凌晨不会落到前一天 |
| 金额精度 | 半分舍入、多笔累计、极值和非法数值；无 float 累积误差，无负金额、NaN、Infinity 或超精度输入 |
| 年付和跨月报销 | 10 月一次年付全额计入 10 月；11 月报销后不增加 11 月费用、不移动 10 月费用 |
| 无需报销 | 计入支出，不计入人员待报销，不允许登记报销 |
| 批量报销 | 同付款人混合 CNY/USD 可结清；不同付款人、重复 ID、已作废或已报销记录被拒绝，事务无部分成功 |
| 差额分配 | 两笔记账 100 和 200 元，实际合计 299 元，分配为 99.67 和 199.33；差额合计 -1 元，原费用仍为 300 元 |
| 并发和重试 | 两个管理员同时报销同一记录最多成功一次；同幂等键重试返回同一结果；编辑与报销竞态不会报销过期金额 |
| 撤销与作废 | 整批撤销后恢复待报销，保留原凭证和事件；已报销不能直接作废；有效性变化正确反映到月报 |
| 历史迁入 | 不自动推断付款人或报销状态；重复迁入无重复数据；未确认和异常记录有可见提示；旧附件仍可下载 |
| 筛选和导出 | 超过 50 条仍能分页查看和全部导出；页面与三张表一致；中文表头、数值金额；公式样式文本按文本保存 |
| 权限和布局 | 普通用户不能读写台账或下载凭证；桌面及 390px 嵌入页按钮可操作、表格可横向滚动，明暗主题可读 |

后端测试以现有 `backend/tests/` 为基础扩充，调整因旧写接口退役而需要变化的测试，同时保留旧资料读取、权限和附件回归覆盖。汇率单元测试用固定模拟响应，不依赖联网。实际 provider 连通性单独检查，不能用联网成功替代金额逻辑测试。
