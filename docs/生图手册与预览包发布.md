# 生图手册与 Windows 预览包发布

本流程只更新静态手册。若 `frontend/src`、`frontend/nginx.conf`、前端依赖或应用构建发生变化，应使用原完整前端发布流程。

## 发行文件

安装包来自 huima-image-mcp 的构建结果，并由 `scripts/huima/prepare-installer-preview.ps1` 核对构建 SHA-256、确认未签名、生成新的发行暂存目录。复制其中的 `assets/image-mcp-release.json`、`assets/downloads/` 到 `frontend/manual/assets/` 对应位置。

EXE 被 Git 忽略，需通过发行文件传输单独放入 Docker 构建上下文。提交清单与 SHA256SUMS，但不要提交 EXE、运行时、个人配置或凭据。发布文件名包含摘要前缀，不覆盖旧包。预览版清单使用 `unsigned-preview`，页面展示未签名状态、版本、字节数与 SHA-256。

## 发布检查

1. 在既有 Windows 虚拟机验收普通用户默认路径安装、开始菜单维护入口、卸载、保留图片和 Key、重装；对比三客户端的其他设置，恢复既有真实试用配置。安装检查仅查询模型列表并发现 MCP 工具，不调用生图。
2. 执行 `pnpm check:all`（MCP 仓库）和 `npm run test:manual`（本仓库 frontend）。核对 EXE 的实际大小与完整 SHA-256。
3. 记录当前生产前端镜像及容器状态，使用当前镜像作为基础：

   ```bash
   docker build -f frontend/Dockerfile.manual \
     --build-arg PREVIOUS_FRONTEND_IMAGE=<当前生产前端镜像> \
     -t ops-extension-frontend:<发行标识> frontend
   ```

4. 先启动只绑定回环地址的候选容器。比较整个 `/usr/share/nginx/html/ext/app` 文件集合及 SHA-256，确认应用与旧哈希资源全部保留。候选环境只请求静态文件，不访问生产 API。
5. 检查手册入口、导航、脚本、样式、Logo、下载清单和 EXE；下载 HEAD 长度及完整 GET 摘要必须匹配清单。检查 Range 下载、CSP、no-cache/no-store 与不存在的 JS 返回 404。浏览器核对未签名文案及下载按钮。
6. 验收通过后，备份服务器发布覆盖配置，将前端镜像改为候选镜像，仅对前端执行 `docker compose ... up -d --no-deps --no-build ops-frontend`。核对公网 HTTPS 手册、下载长度/摘要及健康接口，比较其他容器 ID、镜像和启动时间。
7. 保留原镜像与服务器私有配置备份；若切换失败，只恢复前端镜像及发布覆盖配置。不要更新后端、数据库、Sub2API 或系统反向代理。
