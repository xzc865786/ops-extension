# 使用手册与站点配置优化建议

检查日期：2026-09-30
检查对象：`https://api.tysy.top/docs/` 使用手册（首页、Codex、Claude Code、CC Switch、WorkBuddy、一键配置共 6 个页面及其资源），以及同域名下与之相关的站点配置。

本文列出发现的问题和建议的处理方式，供部署人员和内容维护人员逐项处理。每一项都写明现状（附证据）、建议操作和验证方法。**标注「需负责人确认」的事项涉及业务决策，请先确认再改。**

> 使用手册的源文件不在本仓库，内容类修改需要在服务器 `/docs/` 对应的目录（或手册的源码仓库）中进行。Caddy 配置片段均已在同构环境中用 Caddy v2.10 验证过语法和效果；应用到线上前仍需先 `caddy validate`。

## 一、总体结论

手册整体质量较高，以下方面**已经做得很好，建议保持**：

- **面向新手：** 五步流程清晰，有真实截图，区分了「网站账号 / API 密钥 / 客户端」三个概念，还有安全和计费提示。

- **图片规范：** 所有图片都有替代文字，长页面图片使用了懒加载。

## 二、P0：上线新首页前处理

### A1. 首页宣传的模型与手册不一致

> **已确认（2026-09-30）：** DeepSeek、GLM 后续上线，新首页保留这两个模型。**模型上线时**必须同步完成下面「建议 1」：补充手册，并在渠道中关联分组、配置定价，使其出现在模型广场。

**现状：**
- 新首页写着「Claude · GPT · DeepSeek · GLM 已接入」。
- 使用手册 6 个页面中「DeepSeek」「GLM」出现次数均为 0。
- 旧首页的「支持的模型」只列了 Claude 和 GPT。
- 手册里所有工具的配置说明都只覆盖 OpenAI（Responses / Chat Completions）和 Anthropic 两种协议。

**风险：** 用户按首页宣传来使用 DeepSeek 或 GLM 时，在手册里找不到分组、协议和模型 ID，会直接转为客服咨询或投诉。

**建议（二选一）：**

1. **DeepSeek、GLM 已经可用：**
   - 在手册「03 创建密钥」和「04 连接软件」中补充说明：
     - 它们属于哪个分组
     - 使用哪种协议（通常是 OpenAI 兼容的 Chat Completions）
     - 完整模型 ID
     - 推荐搭配哪些工具（例如 WorkBuddy 可用，Codex 的 Responses 协议是否支持）
   - 在首页「连接软件 → 开发者 API」标签中确认示例同样适用。
2. **尚未开放：** 先从新首页去掉这两个模型，开放后再加回。需要修改 `homepage-designs/03-holo-pop.html` 中的三处：
   - 顶部「已接入」标签（搜索 `已接入`）
   - 钥匙卡上的模型标签（搜索 `class="models"`）
   - 滚动字幕（搜索 `DEEPSEEK`、`GLM`）

**验证：** 首页列出的每个模型，在手册里都能找到对应分组、协议和模型 ID 的说明。

### A2. 手册的 logo 与配色不是官方品牌标识

**现状：**
- 手册页头使用的是一个蓝绿色「H」形图标，主色调为绿色。
- 汇码智能官方品牌标识（Brand Identity v1.0，状态 LOCKED）是「三个石墨色模块汇聚于智能青核心」。
- 官方标准色是 Graphite `#2B2E33` 和 Intelligence Teal `#17CFD8`。
- 新首页已使用官方标识，手册仍是旧 logo。用户从首页点进手册，会看到两套不同的 logo。
- 各页面 favicon 为 `assets/brand-icon.png`，大小 109 KB。

> **品牌名称已确认（2026-09-30）：** 新首页使用「汇码智能」；**使用手册和 Sub2API 后台保留「汇码」**。因此手册只替换图形标识，不使用带「汇码智能」字样的横版组合。

**建议：**

1. 用官方图形标识替换手册 logo，文件在本仓库的 `homepage-designs/brand/`：
   - 页头：用 `huima_symbol_color.svg`（不小于 24px，建议 32px）替换现有的「H」形图标，右侧保留现有的「汇码 / 使用手册」文字。**不要使用** `huima_horizontal_*.svg`，它自带「汇码智能」字样，与手册名称不一致。
   - favicon：`favicon.ico`、`favicon-32.png` 或 `huima_symbol_micro.svg`（专为 16px 设计）。
2. 手册 CSP 是 `img-src 'self'`，logo 文件需要**放到 `/docs/assets/` 下**引用，不能外链。
3. 把主色从绿色调整为品牌色：
   - 按钮、链接、强调色使用 Graphite `#2B2E33`。
   - 选中状态和少量高亮使用 Teal `#17CFD8`。注意品牌规范要求**智能青不用于白底正文大段文字**，它在白底上对比度不足。
4. 页面标题后缀保持「· 汇码」。
5. 遵守品牌规范的禁止项：不拉伸、不旋转、不改色、不加渐变或阴影，详见 `homepage-designs/brand/BRAND_STYLE_GUIDE.md`。

**验证：** 首页、手册、控制台三处的图形标识一致；favicon 在浏览器标签页清晰可辨，文件小于 5 KB。

### A3. 配置脚本下载文件名为 `qiyuan-*`

**现状：** 一键配置页下载的文件名是 `qiyuan-codex-setup.cmd`、`qiyuan-codex-rollback.cmd`，手册正文中出现 6 次。「qiyuan」与「汇码」品牌无关。这是一个**未签名的 .cmd 脚本**，陌生的名字会让用户犹豫是否安全，也不利于客服沟通。

**建议：**

- **只改用户看得到的部分：** 下载文件名改为 `huima-codex-setup.cmd`、`huima-codex-rollback.cmd`，手册正文和截图说明同步修改。
- **不要改脚本内部标识。** `assets/codex-setup-core.js` 中的以下名称已经写进了用户电脑的配置里：
  - Codex 配置里的 `model_providers.qiyuan_docs`
  - 环境变量 `QIYUAN_API_KEY`
  - 备份目录 `qiyuan-docs-backups`
  - 锁文件 `qiyuan-docs.lock`

  贸然改名会导致：已配置用户的回滚脚本找不到备份，重复运行后生成两套配置。如果确实要统一，需要编写迁移逻辑（新脚本识别旧名称并迁移），并完整测试「旧版配置 → 新版配置 → 回滚」的全过程。

**验证：** 在一台 Windows 测试机上依次执行：旧脚本配置 → 新文件名的配置脚本 → 回滚脚本，确认回滚仍能恢复到上一次的配置。

## 三、P1：体验、性能与安全

### B1. 开启压缩传输

**现状：** 手册所有文件都没有压缩传输（带 `Accept-Encoding: gzip` 请求，响应中也没有 `Content-Encoding`）。实测 gzip 后的体积：

| 文件 | 原始 | 压缩后 |
| --- | --- | --- |
| 手册首页 `index.html` | 29.0 KB | 9.9 KB |
| `docs.css` | 24.5 KB | 6.1 KB |
| `docs.js` | 17.1 KB | 4.9 KB |
| 6 个页面与 4 个脚本/样式合计 | 205 KB | 70 KB（减少约 66%） |

**建议：** 在 Caddyfile 的 `/docs/` 规则内加一行 `encode zstd gzip`（见附录 A）。

> **注意：不要把 `encode` 写在站点级别。** 站点级别的压缩会作用于 Sub2API 的 API 响应，可能影响 `/v1/messages` 等流式输出。只写在 `/docs/`（和首页部署手册中的 `/landing/`）规则内即可，已验证这种写法不会影响 API 和 Sub2API 页面。

**验证：**

```bash
curl -sS -o /dev/null -D - -H 'Accept-Encoding: gzip' https://api.tysy.top/docs/ | grep -i content-encoding
# 预期：content-encoding: gzip（或 zstd）
```

### B2. 图片缓存与 favicon 体积

**现状：**
- 包括截图和图标在内的所有资源都是 `Cache-Control: no-cache`，每次打开页面都要向服务器校验一次。
- favicon `brand-icon.png` 为 109 KB，是一张大尺寸 PNG。浏览器每个页面都会请求它，而常规 favicon 只有 1–5 KB。

**建议：**

1. 图片设置 7 天缓存，HTML、CSS、JS 保持 `no-cache`。HTML、CSS、JS 的文件名不带版本号，长缓存会导致更新后用户看不到新版。配置见附录 A。
2. 按 A2 改用官方 favicon（`favicon.ico` 为 1.7 KB）。
3. **更新截图时要换文件名**（例如 `login-v2.jpg`），否则已缓存的用户最多 7 天看不到新图。

> 实测 Caddy 的一个细节：如果先写一条对全部文件的 `Cache-Control: no-cache`，再写一条针对图片的缓存规则，**前者会覆盖后者**。必须像附录 A 那样用两个互斥的匹配条件（图片 / 非图片）分别设置。

**验证：**

```bash
curl -sSI https://api.tysy.top/docs/assets/screenshots/login.jpg | grep -i cache-control
# 预期：cache-control: public, max-age=604800
curl -sSI https://api.tysy.top/docs/ | grep -i cache-control
# 预期：cache-control: no-cache
```

### B3. 手册内不存在的页面返回空白 404

**现状：** 访问 `https://api.tysy.top/docs/nope.html` 返回 404，但页面内容为空、没有类型，用户看到的是一片空白。旧链接失效或用户输错地址时无路可走。

**建议：** 在 `/docs/` 目录放一个 `404.html`（示例见附录 B），并在 Caddy 中用 `handle_errors` 让手册下的 404 返回这个页面（见附录 A）。页面应引用手册自己的 `assets/docs.css`。手册 CSP 禁止内联样式，**不能使用 `style` 属性或 `<style>` 标签**。

**验证：**

```bash
curl -sS -o /dev/null -w '%{http_code}\n' https://api.tysy.top/docs/nope.html   # 预期 404
curl -sS https://api.tysy.top/docs/nope.html | grep -o '<title>[^<]*</title>'    # 预期显示 404 页标题
```

### B4. `robots.txt` 返回的是 Sub2API 网页

**现状：** `https://api.tysy.top/robots.txt` 返回 200，但内容是 Sub2API 前端的 HTML，不是 robots 规则。搜索引擎无法获得有效指引。

**建议：** 在服务器放一个真正的 `robots.txt`（示例见附录 B）：允许收录首页和手册，禁止抓取 API、控制台和扩展路径。再在 Caddy 中用 `handle /robots.txt` 直接返回这个文件（见附录 A）。

**验证：**

```bash
curl -sS -w '\n[%{http_code} %{content_type}]\n' https://api.tysy.top/robots.txt
# 预期：显示 User-agent 等规则，类型为 text/plain
```

### B5. 全站没有 HSTS

**现状：** 首页和手册的响应中都没有 `Strict-Transport-Security`。虽然 HTTP 访问会 308 跳转到 HTTPS，但首次访问仍经过一次明文 HTTP 请求。

**建议：** 在站点级别加入 HSTS（见附录 A）。**分两步上线：**
1. 先设置 `max-age=86400`（1 天），观察一周，确认所有页面和 API 调用都正常走 HTTPS。
2. 再改为 `max-age=31536000`（1 年）。

不要加 `includeSubDomains` 和 `preload`，除非确认 `tysy.top` 的所有子域名都已支持 HTTPS。

**验证：** `curl -sSI https://api.tysy.top/ | grep -i strict-transport-security`

### B6. 分享链接没有预览卡片

**现状：** 手册页面没有 Open Graph 标签（`og:title`、`og:description`、`og:image`）。把手册链接发到 QQ、微信或其他平台时，不显示标题、摘要和图片。客服经常需要把手册链接发给用户，这一点影响较大。

**建议：** 在每个手册页面的 `<head>` 中加入以下标签，内容按页面调整；`og:image` 必须是**完整的 https 地址**：

```html
<meta property="og:type" content="website">
<meta property="og:site_name" content="汇码">
<meta property="og:title" content="使用手册 · 汇码">
<meta property="og:description" content="注册登录、创建 API 密钥、连接 Codex / Claude Code / WorkBuddy，五步完成。">
<meta property="og:url" content="https://api.tysy.top/docs/">
<meta property="og:image" content="https://api.tysy.top/docs/assets/og-cover.png">
```

`og-cover.png` 建议 1200×630，用官方图形标识加「汇码 · 使用手册」文字，搭配浅色背景制作。

**验证：** 把链接发到 QQ 或其他支持链接预览的平台，确认显示标题和图片。部分平台（如微信）对网页卡片有自己的规则，以实际效果为准。

### B7. 安装步骤依赖境外站点，未说明网络问题

**现状：** 手册中的安装来源都是官方境外站点：
- Codex 用 `chatgpt.com` 的安装命令
- Claude Code 用 `claude.ai` 的安装命令
- CC Switch 从 GitHub Releases 下载

手册里没有任何关于网络环境的说明（「网络」「无法访问」「国内」等词出现次数为 0）。在中国大陆的网络环境下，这些地址经常无法访问或速度很慢，新手会卡在第一步，又无从判断原因。

**建议：**

1. 在每个工具的安装步骤旁，以及「常见问题」中，增加「下载或安装失败怎么办」：
   - 说明这些是官方地址，部分网络环境可能访问不稳定；
   - 列出失败时的典型报错（超时、无法解析域名、连接被重置）；
   - 引导联系客服获取帮助，**明确提醒不要从来路不明的网站下载「整合包」或「破解版」**（手册已有类似提醒，可放在一起）。
2. 评估是否提供经过核验的替代来源（需负责人确认）。例如 Codex CLI 与 Claude Code 在 npm 上也有官方发布的包，可通过国内 npm 镜像安装。**上线前需要逐一核实包名、发布者和版本**，并在手册中注明来源。不建议自行托管第三方软件安装包，这涉及许可和安全责任。

**验证：** 请一位不熟悉技术的同事，在不使用任何网络工具的普通网络下按手册安装一次，记录卡住的地方。

### C2. 没有可用模型清单

> **已确认（2026-09-30）：** 采用开启模型广场的方案，操作步骤见 [模型广场开启指南](./模型广场开启指南.md)。开启后在手册中加入链接（下文建议 2）。

### C3. 客服渠道只有 QQ，未提及「我的工单」

**现状：** 手册「联系客服」只提供 QQ 569229275。站点已上线 Ops Extension 的工单功能：普通用户在控制台左侧菜单有「我的工单」，支持附件和进度跟踪。但手册中「工单」出现次数为 0。

## 附录 A：Caddy 配置参考

以下是**需要增加或调整的部分**，不是完整配置。现有 `/docs/` 规则的写法可能与示例不同，请按「增加哪几行」的思路合并进去，保留原有的 `root` 路径和 CSP。修改前备份 Caddyfile，修改后先 `caddy validate` 再重载。

```caddyfile
api.tysy.top {
	# B5：HSTS，先用 1 天观察，确认无误后改为 31536000
	header Strict-Transport-Security "max-age=86400"

	# B4：真正的 robots.txt（文件放在 /srv/huima-site/robots.txt）
	handle /robots.txt {
		root * /srv/huima-site
		file_server
	}

	# 使用手册（在现有规则中增加标注了 B1 / B2 的行）
	handle_path /docs/* {
		root * /srv/huima-docs        # 保持现有路径
		encode zstd gzip              # B1：只在这里压缩，不要放到站点级别

		# 保持现有的 CSP、nosniff、no-referrer 等响应头不变
		# header Content-Security-Policy "…现有内容…"

		# B2：图片缓存 7 天，其余文件每次校验。两个匹配条件必须互斥，否则 no-cache 会覆盖图片缓存
		@docsimg path *.png *.jpg *.jpeg *.webp *.svg *.ico
		header @docsimg Cache-Control "public, max-age=604800"
		@docsother not path *.png *.jpg *.jpeg *.webp *.svg *.ico
		header @docsother Cache-Control "no-cache"

		file_server
	}

	# B3：手册下的 404 返回自定义页面（保持 404 状态码）
	handle_errors {
		@docs404 expression `{err.status_code} == 404 && {path}.startsWith("/docs/")`
		handle @docs404 {
			root * /srv/huima-docs    # 与上面 /docs/ 规则相同
			rewrite * /404.html
			file_server
		}
	}

	# …… 其余现有规则（/landing/、/ext/*、Sub2API 反向代理等）保持不变 ……
}
```

**说明：**
- 如果现有 `/docs/` 规则里已经有一条设置 `Cache-Control "no-cache"` 的 `header`，要**删除它**，改用上面两条互斥的规则，否则图片缓存不会生效。
- `handle_errors` 中的 `expression` 写法兼容 Caddy 2.x 各版本。已在 Caddy v2.10 验证：返回自定义页面，并保持 404 状态码。
- 已验证以上配置不会压缩 Sub2API 页面和 API 的流式响应（`text/event-stream`）。
