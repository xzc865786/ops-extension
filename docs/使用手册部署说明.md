# 使用手册随 Ops Extension 部署

使用手册源码现位于 `frontend/manual/`。它是一套可直接编辑的静态 HTML、CSS、JavaScript、图片和下载文件，无需单独安装依赖、构建服务或启动文档容器。

`frontend/Dockerfile` 在构建 Ops 前端镜像时，将手册复制到 `/usr/share/nginx/html/docs/`。同一 Nginx 容器提供 `/ext/app/` 和 `/docs/`，主项目 Sub2API 与 Ops Extension 仍分别更新。手册随 Ops 前端发布和回滚，不再执行独立的文档发布。

| CC Switch 下载 | 版本号、Windows 安装包（填地址或上传到文件库）、GitHub 发布页 |
| AI 生图 | Windows x64、macOS ARM64/x64 下载开关与发行元数据、文件库或地址来源、按 Sub2API 关联的推荐分组和 Key 补充说明 |
| 分组说明 | 手册“选择分组”页（`groups.html`）的开头说明、黄色提示、分组列表和常见问题。每个分组可填名称、标签、Key 风格、适用软件、倍率数字和倍率说明、一句话介绍、适合场景、主要模型、注意事项，并可设为不在手册显示 |

- **AI 生图例外**：在线下载只使用公开接口的 `image_mcp`，接口失败或下载关闭时不会回退静态清单。教程和其他手册配置仍可使用随包默认值。已移除独立的 `image-mcp-release.json`；新发行包在后台发布，初始兼容值保存在两份一致的默认配置中。外部下载地址需要允许浏览器跨域 HEAD 并公开 `Content-Length`；普通保存不抓取外部地址。
- **工作方式**：手册加载时请求 `GET /ext/api/v1/public/manual-config`。接口不可用或返回的值不合格时，自动使用随手册打包的 `frontend/manual/assets/manual-config.default.json`，页面照常可用。
- **安全**：这些值会写进用户电脑上运行的安装/配置脚本。后端保存时按白名单格式严格校验，手册生成脚本前、脚本运行时各再校验一次。
- **生图历史兼容**：旧配置缺少 `image_mcp` 时补入已核实的 0.1.0 Windows 静态包信息，不要求重新上传；旧历史比较及恢复会提示新增部分采用兼容默认值。Mac 默认关闭，不代表已有安装包。推荐分组只存 `sub2api_id`，必须唯一关联公开条目；改名与分组说明一起发布，公开接口不暴露关联 ID。
- **版本**：每次保存生成一个新版本，记录修改人和说明；可以对比任意版本与当前配置的差异，“恢复到此版本”会生成新版本，旧版本都保留。
- **上传代理**：应用默认上限为 256 MiB；仓库入口 nginx 示例和前端容器 `/ext/api/` 均设为 272m，给 multipart 留余量。环境变量 `MANUAL_FILE_MAX_BYTES` 若已有覆盖，部署时须单独核对。当前生产 Caddy 的 `/ext/api/*` 直连后端，未配置显式请求体上限，生产后端仍为 100 MiB（本次仅只读核查，尚未发布）。
- **文件库**：上传的安装包存放在 MinIO（`manual/` 前缀），通过 `/ext/api/v1/public/manual-files/{编号}/{文件名}` 公开下载，单个最大 256 MiB。如果入口是 nginx，`/ext/api/` 的 `client_max_body_size` 需要不小于 272m（含 multipart 余量）（见 `nginx/ext.conf.example`）。
- **生图文件保护**：上传来源的文件名、大小、SHA-256 从服务端记录读取并覆盖客户端提交值；站内文件地址同样解析记录并保护引用。当前配置引用的文件不可删除；历史文件被删除后恢复会明确报错。上传下载接口支持 GET 与 HEAD；HEAD 检查实际存储对象，未提供 Range 分段能力。原静态安装包的 Range 下载保持不变。
- **分组同步**：“分组说明”页的“从 Sub2API 同步”会用 `SUB2API_ADMIN_API_KEY` 读取 Sub2API 启用中的分组（`GET /api/v1/admin/groups/all`），列出未添加的分组和名称、倍率、Key 风格已变化的分组。勾选后，新分组加到列表末尾；已有分组只更新名称、倍率和 Key 风格，管理员写的说明不会被覆盖。同步只改编辑中的内容，点“保存”后才生效。手册只读取已保存的配置，不直接访问 Sub2API；设为不显示的分组和 Sub2API 分组编号不会出现在公开接口里。
- **默认值**：首次访问时用 `backend/app/manual/default_config.json` 写入版本 1。它必须和手册里的 `manual-config.default.json` 完全一致，后端测试会检查；修改默认值时两份一起改。

## 日常维护

### WorkBuddy 推荐配置升级

本次配置增加默认思考强度、可选档位和按模型匹配的能力例外规则，输入／输出上限允许留空。新安装的默认配置开启思考（默认高，可选低／中／高，仅思考模式）和图片输入；WorkBuddy 的“可用模型”改为逐个列出的模型 ID（gpt-6.1-sol、gpt-6-astra、gpt-6-sol、gpt-6-luna、gpt-5.6-sol、gpt-5.6-terra、gpt-5.6-luna、gpt-5.5、deepseek-v4.1-flash、glm-5.3-flash），不再用 `gpt*` 放行图片模型等不适用的模型。没有匹配规则的模型使用全局默认值，内置规则为空；某个模型不支持图片或思考、或不允许关闭思考时，再在后台添加例外规则。

已有数据库配置不会被仓库默认值覆盖。部署后，在后台“安装与客户端 → WorkBuddy 模型参数”点击“应用 WorkBuddy 推荐配置”，核对规则后保存，生成新的配置版本；“推荐模型”页 WorkBuddy 的可用模型需另外手动改成上面的模型 ID 列表。此按钮仅替换正在编辑的 WorkBuddy 配置，不更改站点地址、Key 分组说明或安装来源；已有用户电脑上的配置和已下载脚本需要重新生成并运行，或按图编辑模型。

- 完整模型 ID 优先于通配规则；通配规则按列表顺序匹配。规则里“跟随默认”的项使用全局开关。
- `/v1/models` 只返回模型 ID，不含能力信息，因此能力只能由后台规则声明。新增模型时，先在“推荐模型 → WorkBuddy → 可用模型”补上完整模型 ID，再按需添加能力例外。
- 同一模型 ID 在多个分组／通道能力不同，当前规则应采用它们共同支持的能力。暂未接入可信的分组能力元数据，不能根据 Key 或模型 ID 猜测通道。
- 已确认某模型不支持图片，在对应规则选择“不支持”。新增模型可直接在后台补规则，无需改配置脚本。
- 上限留空时，脚本省略 `maxInputTokens`／`maxOutputTokens`，不写入 0、空字符串或 null。不填只表示不覆盖客户端配置，仍需核对客户端默认限制和上下文压缩行为。
- WorkBuddy 5.8 的思考开关状态存在客户端自己的数据库里，models.json 只能决定开启后的强度，新模型默认是关闭的。因此默认“允许用户关闭思考”为否：脚本写入 `onlyReasoning: true` 与 `reasoning.canDisableThinking: false`（与 WorkBuddy 自己保存的格式一致），对话里没有开关，始终按所选强度思考。个别模型需要允许关闭时，在例外规则里选“允许”。
- 前后端应一起发布：后端负责新字段校验和历史版本兼容，前端负责能力规则编辑、动态手册和脚本生成。数据库表结构不变。

Windows 安装、配置和恢复脚本共用 `assets/windows-powershell.js` 中的启动检测。修改该文件后，应同步更新安装 CMD 的同名子程序；手册测试会检查两处一致。启动前按完整路径检测系统 PowerShell 5.1 与已有 PowerShell 7，实际写入开始后不换引擎重跑。

验收至少执行 `npm run test:manual`、`npm run build` 和后端 `python -m pytest tests/test_manual_config.py -q`；真实客户端及上游请求验证按 `output/vm-test/测试指南.md` 的 WorkBuddy 专项执行。仅配置文件写入成功不能证明上游已按高强度执行。


Windows 下载脚本必须保留 CRLF 换行。仓库 `.gitattributes` 将 `*.cmd` 指定为 `text eol=crlf`，用于 Git 检出与发布归档；网页生成 CMD 下载时也统一为 CRLF。发布验收除校验文件内容外，应确认 CMD 无单独的 LF 换行，并在 Windows 验证启动入口，避免出现本地可运行、线上下载后命令被截断或窗口闪退的问题。

## 入口代理的一次性调整

对本机 Caddy 入口，将原来的文档静态文件块替换为：

```caddyfile
redir /docs /docs/ 308

handle /docs/* {
    reverse_proxy 127.0.0.1:8088
}
```

使用 `handle` 保留 `/docs/` 前缀，不能继续使用会剥离前缀的 `handle_path`。本服务器 Caddy 使用宿主网络，所以 `127.0.0.1:8088` 指向 Ops 前端映射端口；其他 Docker 网络部署应根据网络实际情况改用容器服务名。原有 Sub2API `/docs/batch-image` 路由继续放在文档通配路由之前。

完整示例见 `nginx/manual.caddy.example`；Nginx 入口示例见 `nginx/ext.conf.example`。文档的 CSP、缓存策略和其他响应头由 Ops 前端 Nginx 提供，原有文档目录可以保留作迁移备份，但不再作为线上文件源。
